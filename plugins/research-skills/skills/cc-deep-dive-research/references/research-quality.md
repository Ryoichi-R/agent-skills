# 再調査の品質判定

機械検証と意味評価を分ける。CLIのPASSは意味の正しさを保証しない。

## leadの固定ルーブリック

各観点を0（不足）/1（部分的）/2（充足）で評価する。文字数・URL数を加点しない。

| 観点         | 2点の条件                                                     |
| ------------ | ------------------------------------------------------------- |
| 質問への適合 | 元質問・不満点・時点に直接答え、重要な未回答を隠さない        |
| 具体性と条件 | 母集団・年度・単位・適用条件・例外を原典と照合して説明する    |
| 根拠の追跡性 | 原資料、hash/行範囲または取得本文、主張との関係が一致する     |
| 反証と訂正   | 不都合な根拠も扱い、前回の結論の維持/限定/訂正/撤回を説明する |
| 不確実性     | 未読・不明・不存在・取得障害を区別し、検索範囲と限界を示す    |
| 可読性       | 再調査後の回答を先に示し、必要な詳細を課題ごとに読める        |

重要な主張の捏造、引用先不一致、対象の違う数値流用、取得失敗を不存在扱い、未確定completeは重大指摘。重大指摘を残してcompleteにしない。事例数は問いに必要な場合だけ評価する。

## 評価手順

同じ問いで前段・改修前後のレポートを比較し、期待資料・引用範囲・結論をfixture側に固定する。調整用と未使用holdoutを分ける。正解集合付きfixtureでのみ検索recallを計算し、実資料全体のrecallとは呼ばない。

見落とし必須fixtureは全件回収、捏造出典0・重大誤結論0・引用不一致0・途中complete誤表示0。重要な意味評価ケースは3回行い揺れを記録する。live受入はローカル見落とし、Web→local往復、反証訂正の最低3ケースで、1件はcheckpoint→resumeを含める。実行できないケースはNOT_RUNとする。

同じ原発表の転載や保存コピーはorigin_idを共有する。独立性不明を独立した2件と数えない。公開/改訂/適用日不明はnullを維持し、mtime/取得日を新しさの代用にしない。

ownerによる実資料受入は別欄。fixtureやleadの評価をowner受入と記録しない。
