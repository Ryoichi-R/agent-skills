# 情報源の優先順位と信頼性評価基準

## 優先順位（高い順）

| 順位 | 情報源                     | 説明                                              |
| ---- | -------------------------- | ------------------------------------------------- |
| 1    | 公式ドキュメント・一次情報 | RFC、公式リファレンス、公式ブログ、リリースノート |
| 2    | ローカル資料（最新）       | skill-source 内の資料で、更新日が直近のもの       |
| 3    | 信頼性の高い二次情報       | 技術書、査読付き論文、著名な技術ブログ            |
| 4    | ローカル資料（古い）       | skill-source 内の資料で、更新日が古いもの         |
| 5    | 一般的なWeb情報            | Stack Overflow、Qiita、個人ブログ等               |

## 信頼性評価のルール

### 鮮度の重要性

- **時点依存の話題**（価格、バージョン、API仕様、ニュース）: 発行日・更新日を必ず明記する
- ローカル資料の `modifiedAt` とWeb情報の公開日を比較し、より新しい方を優先する
- 1年以上前の情報は「古い可能性あり」と注記する

### 矛盾解消の手順

1. **情報源の権威性を比較**: 公式 > 非公式、一次情報 > 二次情報
2. **鮮度を比較**: 新しい情報を優先（ただし、一次情報の古い記述が二次情報の新しい解釈より正確な場合あり）
3. **複数Web情報の一致度を確認**: 複数の独立した情報源が一致する場合は信頼性が高い
4. **判断を明記**: どちらを採用し、なぜそちらを選んだかを回答に記載する

### ローカル資料の特別扱い

- ローカル資料は**組織固有の文脈**を含む可能性がある（社内ルール、カスタム設定等）
- 一般的な技術情報についてはWeb情報を優先するが、組織固有の設定・手順についてはローカル資料を優先する
- ローカル資料とWeb情報が矛盾する場合は、矛盾点を明記した上で両方の情報を提示する

### 深堀りローカル情報の扱い

- 深堀りローカル情報（ステップ3で取得）は、通常のローカル資料（ステップ1で取得）と同じ優先順位で扱う
- 発見経路が異なるだけで、情報源としての性質は同一である
- 矛盾解消時はステップ1のローカル情報と同等の信頼性として評価する
