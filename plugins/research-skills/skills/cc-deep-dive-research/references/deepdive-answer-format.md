# 精査レポート出力テンプレート

## テンプレート構造

```markdown
# <元の調査タイトル> — 詳細調査

元調査: `<入力ファイルパス>`
作成日: YYYY-MM-DD

## 調査対象トピック

精査対象として選定したトピック一覧と選定理由。

| #   | トピック | 選定理由 | 求める情報タイプ                         |
| --- | -------- | -------- | ---------------------------------------- |
| 1   | ...      | ...      | 具体例 / 統計 / 判例 / 比較事例 / 実装例 |

## トピック1: <トピック名>

### 元の記述

> 元研究からの該当箇所を引用

### 具体的事例

- 事例1: ...（出典: [DD-W1] [タイトル](https://example.com)）
- 事例2: ...（出典: [DD-L1] [タイトル](<resolved-source-root>/path/to/file.md)）

### 統計・データ

- ...

### 分析

元の主張との整合性、新たに判明した点。

- **補強**: 元の主張を支持する根拠
- **反証**: 元の主張と矛盾する根拠（該当がない場合は「該当なし」と明記）

## トピック2: <トピック名>

（同構造を繰り返す）

...

## 総合考察

全トピックを横断した考察。元の結論に対する補強・修正点。

## 推奨改善事項

（レビューゲートで p2 判定された推奨事項がある場合のみ記載）

## 出典

- [DD-L1] [タイトル](<resolved-source-root>/path/to/file.md)（検索キーワード: xxx）
- [DD-W1] [タイトル](URL)（参照日: YYYY-MM-DD）
- [ORIG-L1] [タイトル](<resolved-source-root>/path/to/file.md)（元調査から引用）
```

## 出典タグ体系

| 種別         | タグ                                   | 形式                                                           | 説明                               |
| ------------ | -------------------------------------- | -------------------------------------------------------------- | ---------------------------------- |
| 精査ローカル | `[DD-L#]`                              | `[DD-L#] [タイトル](<resolved-source-root>/path/to/file.md)`   | 本調査で新たに発見したローカル資料 |
| 精査Web      | `[DD-W#]`                              | `[DD-W#] [タイトル](URL)（参照日: YYYY-MM-DD）`                | 本調査で新たに発見したWeb情報      |
| 元調査引用   | `[ORIG-L#]`, `[ORIG-W#]`, `[ORIG-DL#]` | `[ORIG-L#] [タイトル](<resolved-source-root>/path/to/file.md)` | 元調査の出典を参照する場合         |

### リンク記法の注意

- ローカルファイルは、実行時に解決した `<resolved-source-root>/` からの絶対パスを使用する
- Web URL は `https://` で始まる完全 URL を使用する
- タイトルはファイル名（拡張子除く）または記事タイトルを使用する
- テンプレート内の例示には、実在する特定資料の名称を使わず、`LLMの仕組み` のような汎用的な架空名称を使用する。実際の精査レポートでは、出典追跡性を保つため原資料の正式名称を改変しない
- パスに括弧・スペース等の特殊文字を含む場合は URL エンコード（`%28` `%29` 等）するか `<URL>` 形式を使用する

### 出典タグ変換表（入力タグ → ORIGタグ）

入力ファイルの出典タグを本レポートで引用する際は、以下のマッピングで変換する:

| 入力タグ | ORIGタグ     | 説明                   |
| -------- | ------------ | ---------------------- |
| `[L#]`   | `[ORIG-L#]`  | ローカル資料の引用     |
| `[W#]`   | `[ORIG-W#]`  | Web情報の引用          |
| `[DL#]`  | `[ORIG-DL#]` | 精査ローカル情報の引用 |

変換ルール: 入力タグのプレフィックスに `ORIG-` を付与し、番号はそのまま保持する。

## 必須セクション

以下のセクションは必ず含めること:

1. タイトル（`# <タイトル> — 詳細調査`）
2. メタ情報（元調査パス、作成日）
3. `## 調査対象トピック`
4. `## トピックN: <トピック名>`（最低3つ）
5. `## 総合考察`
6. `## 出典`

## 孤立タグ検出アルゴリズム

レポート出力後、以下の手順で孤立タグを検出する:

1. 本文からコードブロック（` ``` ` で囲まれた範囲）を除外した上で、正規表現 `\[(DD-[LW]\d+|ORIG-[LW]\d+|ORIG-DL\d+)\]` でタグを抽出する
2. 出典セクションの全エントリタグを同様のパターンで抽出
3. **孤立タグ（本文→出典）**: 本文に存在するが出典セクションに対応エントリがないタグ
4. **未参照タグ（出典→本文）**: 出典セクションに存在するが本文から参照されていないタグ
5. 孤立タグまたは未参照タグが1件以上ある場合、レビューゲートで `pass: false` とする

## 機密情報保護ルール

レポート出力前に、以下のパターンに合致する文字列をマスクする:

| パターン                                | 説明             | マスク表記               |
| --------------------------------------- | ---------------- | ------------------------ |
| APIキー（`sk-`, `pk-`, `api_key=` 等）  | トークン/APIキー | `[REDACTED:API_KEY]`     |
| メールアドレス                          | 個人情報         | `[REDACTED:EMAIL]`       |
| 秘密鍵（`-----BEGIN.*KEY-----` 等）     | 暗号鍵           | `[REDACTED:PRIVATE_KEY]` |
| AWS/GCP/Azure のクレデンシャルパターン  | クラウド認証情報 | `[REDACTED:CREDENTIAL]`  |
| パスワード（`password=`, `passwd=` 等） | 認証情報         | `[REDACTED:PASSWORD]`    |

## タイムゾーン規約

- タイムスタンプ（ファイル名の `YYYYMMDDTHHmmssZ`）: UTC固定
- 作成日（`YYYY-MM-DD`）: UTC固定
- 出典の参照日（`YYYY-MM-DD`）: UTC固定
- 全ての日時は UTC で統一し、ローカルタイムゾーンは使用しない
